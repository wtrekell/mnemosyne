# Researcher: Design

Status: draft. Not yet built.

This file holds everything about the researcher that is not part of the agent file: why it is built this way, how the score was set, the checks, rules, skill requirements, and open items. The agent definition is in [10-58-49-agent.md](10-58-49-agent.md).

## 1. Parts

Claude Code offers four ways to shape an agent. This design uses three.

| Part | Location | Holds | Why this part |
| --- | --- | --- | --- |
| **Agent** | `.claude/agents/researcher.md` | The rules that apply to all research: source labels, score, report format, quoting. | An agent runs in its own context and returns only its result, which keeps long research out of the main session. It receives only its own body as instructions, so every rule it applies must be in that body. |
| **Skills** | `.claude/skills/research-<kind>/SKILL.md` | What one specific kind of research covers and what its output adds. General research needs no skill. | Skills load only when needed. The agent loads one only when the request calls for that kind of research, so adding a skill needs no change to the agent. |
| **Checks** (hooks) | `.claude/settings.json`; script in `scripts/` | A final check on the report that the researcher cannot skip. | Agent and skill instructions are guidance the model reads. Hooks are enforced. Hooks in project settings run in every session, including untrusted folders and non-interactive runs; hooks in an agent file do not. |
| **Rules** | `.claude/rules/` | Not used for now. | See section 5. |

## 2. Agent field choices

| Field | Reason |
| --- | --- |
| `description` | Claude reads this to decide when to hand work to the agent, so it states the trigger plainly. |
| `tools` | Write and Edit are for reports and the links between them. The two context7 tools come from the context7 plugin and look up current library documentation. No shell access, because research does not need it. |
| `model` | Inherit for now. Revisit after first use. |
| `skills` | Preloading puts the full text of every listed skill into context at start. Leaving this empty lets the agent load a skill only when a request calls for one. The field controls preloading only; the agent can still load any project skill through the Skill tool. |
| `hooks` | Checks live in project settings so they always run (section 4). |

## 3. Score

Proposed. Confirm the multipliers after first use (section 7).

Each source is scored on three dimensions.

| Dimension | 1.4 | 1.2 | 1.0 | 0.8 |
| --- | --- | --- | --- | --- |
| Trust (label) | Official | Reputable, Trusted | Unconfirmed | — |
| Setting | — | Organized | Individual | Community |
| Age | — | Under 3 months | 3 to 9 months | Over 9 months |

- Score = Trust × Setting × Age.
- Age is measured from the date in the source's citation.
- Ignore sources get no score.
- Official sources are exempt from age and always take 1.0 for it.
- A claim's backing is the highest score among its sources.

### Conflicts

When sources conflict, the source whose score is higher by 0.4 or more is preferred, and the report notes the other. Otherwise the report shows both.

### Reasons

- 1.0 is the average for each dimension. Each step above or below the average moves the multiplier by 0.2.
- Reputable and Trusted pass the same test, so they share a multiplier. The difference between an organization and an individual is carried by Setting.
- An organized setting is worth more than an individual one, because someone other than the author chose, edited, or published it.
- Official sources are exempt from age because the owner of a subject defines it. The newest official version is used because it replaces earlier ones.

## 4. Checks

Checks are enforced by hooks declared in project settings (`.claude/settings.json`), not in the agent file. The script is referenced as `${CLAUDE_PROJECT_DIR}/scripts/...`.

1. A `SubagentStop` hook with matcher `researcher` runs the script when the researcher tries to finish. The script checks the report the agent is returning (agent process step 8) and blocks finishing with `decision: "block"` and a `reason` until the report passes. The reason is delivered to the agent as its next instruction.
2. The script is deterministic: the same file always gives the same result. It uses no network and no model calls.
3. Claude Code overrides a block after eight consecutive continuations. The count resets each time the agent calls a tool, so fixing work does not hit it.
4. The checks run unless the person running Claude Code switches hooks off for that run. That is outside this spec.

| Check | Fails when |
| --- | --- |
| Front matter | Any of the five fields is missing or empty. |
| Sections | Findings, Appendix A, or Appendix B is missing. |
| Next searches | Appendix A has more than five entries. |
| Source list | A source has no label or no reason. |
| Claim map | A claim has no source, a `Depends on` ID does not exist, or a Role does not follow from the `Depends on` column. |
| Weak foundations | A weak foundation claim is not named in the summary. |
| Quote limit | Quoted words exceed 10% of the report. |
| Ignore sources | A source labeled Ignore backs any claim. |

Judgments the script cannot make, such as whether a label or a quote is right, stay with the agent.

## 5. Rules

Not used for now. Rules load into every session in the project, including subagents such as this one. A rule without `paths` loads at start; a rule with `paths` loads when a matching file is read or edited. The researcher's instructions already live in its agent file, so a rule would repeat them and load them into sessions that don't need them. Revisit with the deferred report format (section 7).

## 6. Skill requirements

The agent handles general research without a skill. A skill is added only for a specific kind of research that needs its own definition. Each is named `research-<kind>`, and its file must state:

| Item | Content |
| --- | --- |
| `description` | When to use it, written so the agent can match it to a request. |
| Scope | What this kind of research covers and leaves out. |
| Where to look | Source types to favor, beyond the general rules. |
| Added sections | Any report sections it adds to the standard format. |

Skills may tighten the source rules but may not loosen them.

Starting skills:

| Skill | Covers |
| --- | --- |
| `research-build` | What would inform building something: existing tools, services, and code libraries that work in the project's programming language. Example: options for watching online discussion boards for keywords and saving matching threads. Like all research, it ends in a report; it does not write a build plan. |

## 7. Open items

1. **Report format, destination, and storage (deferred).** Deferred until the rest of the spec is settled. It covers:
   - where reports are saved
   - the file template: headings, date format, table layouts, label words in table cells, inline citation syntax
   - source IDs
   - how quoted words and report words are counted for the quote limit
   - what Appendix B adds beyond sources and claims, such as a search log and rejected sources
   - how links between reports are stored
   - how a follow-up request names the report it follows
   - how the check script finds the report the agent is returning
   - whether a path-scoped rule should guide other sessions that edit reports
2. **Viewpoint method** for social media and forums. Six Thinking Hats is the starting candidate. Confirm it through its own research.
3. **Model choice.** Confirm after first use.
4. **Score multipliers.** Confirm the proposed values (section 3) after first use.
